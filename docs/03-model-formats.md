# 03 — Model files and generation

nutllm milestone 3 reads the safetensors container directly. The file is
opened read-only and memory-mapped; tensor views point into that mapping.
Malformed lengths, integer overflow, unsupported dtypes, out-of-range offsets,
missing tensors, and incorrect shapes are rejected before inference.

## Supported safetensors subset

The current loader accepts contiguous, little-endian `F32` tensors. Matrix
weights use the conventional Llama safetensors names and external
`[output, input]` layout:

```
model.embed_tokens.weight
model.layers.N.self_attn.{q,k,v,o}_proj.weight
model.layers.N.mlp.{gate,up,down}_proj.weight
model.layers.N.{input_layernorm,post_attention_layernorm}.weight
model.norm.weight
lm_head.weight
```

External projection matrices are transposed once into nutllm's internal
`[input, output]` layout. Embeddings and `lm_head` remain `[vocab, dim]`.
Every expected dimension is checked exactly.

Safetensors itself normally stores tensor data, not a complete architecture
configuration. Checkpoints produced for nutllm therefore include these string
entries in `__metadata__`:

```
nutllm.layers       nutllm.heads       nutllm.dim
nutllm.head_dim     nutllm.ffn_dim     nutllm.vocab_size
nutllm.max_seq      nutllm.eos_token
```

The checked-in two-layer fixture is generated by
`scripts/make_tiny_checkpoint.py`. It has zeroed transformer projections and a
small output head that deterministically maps `H` → `i` → `!` → EOS. This
exercises the mmap, name mapping, transpose, tokenizer, forward, sampling, and
stopping paths without a network download.

## CLI

The model and byte-BPE files are deliberately separate:

```bash
./build/nutllm \
  --model tests/fixtures/tiny.safetensors \
  --vocab tests/fixtures/tiny.vocab \
  --merges tests/fixtures/tiny.merges \
  --prompt H --max-tokens 8
```

The default is deterministic greedy sampling. `--temperature`, `--top-p`, and
`--seed` enable reproducible nucleus sampling.

## Compatibility boundary

This milestone proves the complete file-to-token engine on a synthetic
checkpoint. Typical public Llama checkpoints use `F16`/`BF16`, an external
`config.json`, and SentencePiece or Hugging Face tokenizer assets. Those
adapters are not implemented yet, so a stock 1B–3B checkpoint has not been
claimed as validated. The milestone status remains partial until one is run
and its output is compared with a reference engine.
